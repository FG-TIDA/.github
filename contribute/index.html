How to contribute to TIDA

TIDA work is organised in work items. Every work item moves through the same lifecycle, and you can contribute at either end of it: improve a work item that exists, or submit a new one.

The lifecycle of a work item

A work item enters the TIDA DataTracker as Submitted. The TIDA DataTracker is the official record and holds the state of every work item; the GitHub repository shows it.

Work Item States:

Submitted
Submitted to the TIDA DataTracker and sent either to Incubation or to a working group. It stays Submitted until that group decides.
Rejected
Declined by Incubation or by the working group.
Draft
Adopted by a working group, or by the new working group Incubation formed. The repository exists and the group writes the work item.
Under review
The working group reviews the draft. Changes still arrive as pull requests.
Published
The working group has approved the work item and the editors have published it. The work item is final.
Withdrawn
Possible from any state. The work item stays in the TIDA DataTracker record.

How to contribute

Contribute to an existing work item

The work item lives in its working group's GitHub organisation. You propose changes; the working group decides.

Applies while the work item is Draft or Under review
  1. 1
    GitHub

    Find the work item

    Open your working group's GitHub page, for example github.com/fg-tida-wg2. Its table of deliverables links each work item's published site, PDF and repository (wg<n>-<acronym>-<name>). The chairs and mailing list are listed there too.

  2. 2

    What do you want to do?

    Change the text

    Open a pull request

    1. In the browser: open a file under src/doc/, click the pencil, choose Propose changes.
    2. Or with Git: branch, edit, push, then open a PR against main.

    Never push to main directly.

    Report a problem or ask a question

    Open an issue

    A clear title and a short description of what is wrong and where is enough to start.

    Discuss direction or larger questions

    Write to the mailing list

    Use the list linked on the WG page. Raise it with the group before drafting anything big.

  3. 3
    GitHub

    The working group reviews

    Every pull request is reviewed by the working group before it is merged, so each change keeps a review and decision history.

  4. 4
    GitHubTIDA DataTracker

    Merged into main

    Each push to main rebuilds the HTML site and PDF and publishes them to GitHub Pages. The same build is sent to the TIDA DataTracker, which always holds the latest working copy of the work item.

  5. 5
    GitHubTIDA DataTracker

    Release: tag vX.Y becomes revision X.Y

    When the editors tag a release, the PDF, source archive and a manifest go to the TIDA DataTracker, which records revision X.Y of the work item.

    Merges between releases update the working copy only. They do not create a revision.

  6. ●
    Your contribution is input, not adopted text. It becomes part of the work item only through the working group's review and the appropriate FG-TIDA process. Everything you do in the repository follows the ITU-T and FG-TIDA participation, conduct and IPR rules.

Submit a new work item

You draft the work item from the template and submit it in the TIDA DataTracker. The TIDA DataTracker is the official record.

Takes a work item from Submitted to Draft
  1. 1

    Where does it belong?

    It fits an existing working group

    Send it to that working group

    Pick the group in the submission form (step 3).

    It needs a new working group

    Send it to Incubation

    Pick Incubation in the form.

  2. 2
    GitHub

    Draft it from the work item template

    On FG-TIDA/spec-template click Use this template, create the repository in your own account, and fill in the abstract, authors and chapters. Every push to main builds a site and a PDF you can review and share.

  3. 3
    TIDA DataTrackerSubmitted

    Submit it in the TIDA DataTracker

    Sign in, open the contribution form and enter the title and abstract, the target (Incubation or a working group), and the document (PDF, DOCX, PPTX, TXT, Markdown or XML, up to 10 MB). Include the link to your draft repository: it ties the TIDA DataTracker record to GitHub and switches on the synchronisation below.

    The work item is Submitted straight away and goes to the group you chose.

  4. 4
    TIDA DataTrackerMailing listSubmitted

    The group decides

    The work item stays Submitted until the group decides. Either way, its state changes.

    Sent to Incubation

    Incubation decides

    Rejected if Incubation rejects it.

    Draft if it accepts: a new working group is formed, chartered from wg-charter-template (wg<n>-<acronym>-charter), and the work item moves into it.

    Sent to a working group

    The working group decides

    Rejected if the group rejects it.

    Draft if the group adopts it.

  5. 5
    GitHubTIDA DataTrackerDraft

    The working group repository is created

    On acceptance the repository is created from the template inside the working group's organisation as wg<n>-<acronym>-<name>, with title and authors filled in from the TIDA DataTracker. The TIDA DataTracker's repository link is updated to it.

  6. ●
    It is now an existing work item. From here, everyone contributes through the path for an existing work item.

GitHub and the TIDA DataTracker stay in sync

Once a work item's TIDA DataTracker record is linked to its repository, the two stay in step without anyone copying files. Each row runs automatically, in the direction of the arrow.
